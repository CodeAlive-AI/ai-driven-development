# First Principles Framework (FPF) - Core Conceptual Specification

> A standards-style pattern language for making reasoning in difficult engineering, research, management, and mixed human/AI work explicit, reviewable, and improvable.

- **Author:** Anatoly Levenchuk, with AI-assisted development and review
- **Version:** October 2026
- **License:** [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) for original framework content; third-party material retains its own terms.
- **DocID:** `FPF` within **FPF Library**.
- **Status:** Normative Core, eternal alpha: already used in working projects and development programs, while still evolving.

Begin with a working question or a worthwhile occasion to examine ordinary work; FPF helps make the reasoning explicit enough to review and improve.

Before selecting framework guidance, read and apply [Using FPF Library](../../library/USING-FPF.md). It explains how to search the Table of Contents and available publications, then read and apply the relevant pattern. If a reading test explicitly limits the reader to an isolated excerpt, use only the materials supplied for that test.

Check that a link has opened the intended pattern or section. If it has not, treat that return as unresolved. For an older link without a label, find the former heading in a saved edition or the file’s history and copy the complete PatternID or SectionRef. Follow [Resolve a portable reference](../../library/USING-FPF.md#resolve-a-portable-reference) with the complete PatternID or SectionRef and any requested edition.

After the Table of Contents, the Readme’s `Practical entries` bring together ordinary examples of using one pattern and selected Practical-Use Cards for reasoning with several. For other FPF, DPF or LPF questions, look up the applicable patterns in the Table of Contents and use those patterns.

The FPF Architectural Reference explains the cross-cutting ideas and the usual sequence for applying a pattern. Its **Big FPF Storylines** connects a worked question to the framework’s Architectural Rationale, shared sources, profile choices and the conditions for using the whole combination.

The pattern bodies contain the normative Solutions, boundaries, worked examples and checks. E.8 governs pattern form. Use E.11.PUA for applying a particular pattern and E.11.PUR for coordinating pattern uses when those questions arise.
