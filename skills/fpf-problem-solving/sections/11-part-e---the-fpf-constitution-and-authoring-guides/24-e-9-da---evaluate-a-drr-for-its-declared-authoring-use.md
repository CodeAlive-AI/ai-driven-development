## E.9.DA - Evaluate a DRR for Its Declared Authoring Use (Decision-Adequacy CharacteristicSpace)

> **Status:** Stable

### E.9.DA:1 - Problem frame

Use `E.9.DA` to judge whether a particular version of a `DRR` can support a declared FPF authoring use. The use can be pattern drafting, host amendment, distribution across selected loci, carrying an accepted decision or source use through subsequent authoring, or deciding a scope boundary, split, or architecture hold. Specify the exact C.2.1 episteme identity only when the judgement or a named later reliance needs it. E.9.DA supplies the questions for this object and the reusable meanings of its coordinates.

For other questions, use `E.21` to judge an authored pattern version, `E.19` to review an FPF pattern edition or bounded subset for admission or refresh, and `F.19` to repair wording, with `E.10` for cues and unresolved meanings. Use `C.16`, `A.17`, `A.18`, and `A.19` for measurement law.

First read the DRR in its declared use and state the working problem, selected answer, practical change, first drafting action, and boundary. If the DRR selects a broad authoring rule, inspect the effect on the actual host by comparing its predecessor and proposed versions before preparing any optional assessment or result materials.

A formally valid `DRR` can leave the author unable to draft. It may summarize sources without deciding, name neighbors without assigning obligations, hide rejected alternatives, leave trigger words unresolved, or omit the first drafting action.

**What is being evaluated?** One DRR version for one declared FPF authoring use and qualification window. Identify assessment work, a reusable coordinate result, witnesses, records, status use, assurance, acceptance, and later repair separately when the case involves them.

### E.9.DA:2 - Problem

`E.9` defines how to decide and record FPF content, the ordinary minimum DRR form, and the exact decision-work, result, and C.2.1 identities to establish when a claim or named reliance needs them. To judge adequacy, examine whether the DRR under review settles enough for the declared downstream use. A reviewer can approve the headings, source volume or prose while the author still has to invent a decision.

Recurring failures:

1. The decision question is broad or implicit.
2. The selected answer is a summary rather than a decision.
3. Alternatives, rejected options, and outside-decision items are not closed.
4. Receiving loci are named but not assigned content obligations or non-obligations.
5. The selected FPF content architecture is explicit but wrong.
6. Source use is copied without saying what changed in the accepted decision.
7. Architecture descriptions, views, graphs, packets, or notes are treated as the FPF decision.
8. Administrative state becomes adequacy evidence.
9. Ordinal adequacy values become repair targets, so the `DRR` gains source rows, locus tables, boundary catalogues, or review proof without making either the selected answer or the first drafting action more decisive.

### E.9.DA:3 - Forces

| Force | Tension |
|---|---|
| Decision completeness vs concise rationale | A `DRR` must settle enough to guide drafting while leaving authors to write the final pattern prose. |
| Exactness vs drafting freedom | The `DRR` fixes selected answers and boundaries; authors still write usable pattern text. |
| Source preservation vs synthesis | Source distinctions matter, but the `DRR` must state FPF decisions. |
| Multi-locus coordination vs EoC boundary | One decision can affect many patterns while one `DRR` adequacy claim stays scoped. |
| Architecture selection vs address completion | Every locus can be assigned and still be the wrong split or merge. |
| Affordability vs completeness | Ordinary bounded review uses only the questions needed for the live judgement; an explicitly requested reusable evaluation covers every coordinate with stable values and evidence. |

### E.9.DA:4 - Solution

Start with the decision itself. Read the DRR under review in its declared authoring use. Can a practitioner or author recover the working problem, selected answer, practical change, selected loci, first drafting action, and boundary without inventing decisions or decoding avoidable formality? Settle that question before constructing any optional evaluation materials.

The following result suffices for an ordinary bounded review.

- the exact DRR and declared authoring use;
- substantive findings, repaired DRR text, or the unchanged checked DRR when the review is clean;
- the actual predecessor/proposed host evidence when the DRR selects a broad language, ontology, or authoring rule;
- the first drafting action or first repair; and
- the stop or reopen condition.

Plain prose can carry this result. Reserve an assessment-work record, application object, aggregate result episteme, precision-profile record, witness package, or evidence-use package for a use that needs it.

Use the complete coordinate result when a complete reusable evaluation was explicitly requested or when a named later reliance needs stable coordinate values. Materialize the exact characteristic-space configuration, semantic evaluation Method, A.6.1 application, result episteme, witnesses, or evidence-use relations only when that receiving use depends on their identities.

A reusable coordinate result can exist without a semantic Method, A.6.1 application, or dated Work. Decide separately whether the receiving claim uses each identity. A claim may use a Method, or an exact application with its actual bindings, without asserting Work.

If the claim asserts dated `U.Work`, establish the Method enacted, every precise performer's A.13 core, and independent A.15.1 Work admission. Add an A.6.1 application only when the claim uses an independently declared operation and its obtaining application. Establish any relation between application and Work separately. Use F.6 only when the result needs precise assignment-bound attribution.

Before assigning coordinates, make one bounded search for an important question the DRR omitted. Inspect the governed problem, the problem-owning practice, current sources, the strongest live alternative, failure and recovery cases, and direct consumers. If an omitted question would change the answer, architecture, source use, consumer obligation, first drafting action, or stop, return it as a substantive finding before completing the coordinate judgement.

In either branch, distinguish the checked DRR, evaluation specification, action or Work, application, result, record, evidence use, status use, authority, and later repair. A compact result can omit identities its receiving use does not need. A claim that asserts Work must still establish the facts required for that Work.

For a broad language or ontology rule, use the predecessor and proposed versions of the actual host to judge `DraftingActionability`, `LexicalAndNamingClosure`, and precision restoration. A promise in the DRR, complete table, test in another lane, or invented fact pack cannot establish how a practitioner can use that host. Require both formal precision and plain comprehensibility.

#### E.9.DA:4.3 - Ordinal coordinate scale and effective floor

| Value | Label | Meaning for a `DRR` decision-adequacy coordinate |
|---:|---|---|
| 0 | `absent` | The coordinate is not expressed for the declared authoring use. |
| 1 | `namedOnly` | The coordinate is named or implied, but cannot carry decision reliance. |
| 2 | `partiallyExpressedForDeclaredUse` | The coordinate is present but incomplete, fragile, or too narrow. |
| 3 | `sufficientlyExpressedForDeclaredUse` | The coordinate can carry the declared authoring use, with limits visible. |
| 4 | `wellExpressedForDeclaredUse` | The coordinate is clearly expressed with direct evidence and boundary protection. |
| 5 | `exceptionallyExpressedForDeclaredUse` | The coordinate is exceptionally expressed across reinforcing loci and cases without hiding cost or neighbour loss. |

When a complete reusable coordinate evaluation is produced, each ordinal value is a content-evaluation claim about the exact checked DRR under the declared use and window. In an ordinary bounded review, the same scale may guide judgement without materializing a measure, Work record, result episteme, assurance, acceptance, or reward.

Every required E.9.DA coordinate has a default floor of `3 sufficientlyExpressedForDeclaredUse`. The review request, an accepted decision, or an `E.22` question frame fixes the required authoring use. Use the E.9.DA default unless a source declares a higher floor for all coordinates or for named coordinates before the evidence is judged. Record the source of each raised floor.

Once the evaluator has seen the result, they may not lower a floor, narrow the use or selected loci, or shorten the qualification window to make the DRR admissible. A diagnostic evaluation with a lower target may report values. It cannot yield `admissibleForDeclaredAuthoringUse`.

#### E.9.DA:4.4 - Required decision-adequacy coordinates

Before assigning values, run the bounded omitted-question search from §4. Ask whether the DRR omitted an important question that would change its answer, content architecture, source use, consumer obligation, first drafting action, or stop. Inspect only enough of the governed problem, problem-owning practice, current sources, strongest live alternative, failure and recovery cases, and direct consumers to answer that question.

If the search finds an important omitted question, state it as a substantive finding before closing the coordinates. Reassess each affected decision, architecture, source-use, actionability and boundary coordinate under its value rule, keeping the required use fixed. When the search finds no such question, an ordinary clean review needs no separate ledger. A reusable result records the checked basis and clean disposition its named reliance needs.

For a framework-architecture decision, recover the practice field and the full use the initiating problem and sources require before evaluating the proposed owner. Inspect the decisive E.4.PFAD comparison, including any current framework boundaries that the new material calls into question.

A correct list of suppliers, a suitable carrier, closed alternative rows, or successful use of a newly written application can each support a narrower conclusion. None by itself establishes that the previous architecture already supplies the whole. Preserve each result at its demonstrated scope. Leave the architecture conclusion open when the required field or redistribution comparison is absent.

#### E.9.DA:4.4a - Result-row discipline and calibration

Use the question-to-ground and result-acceptance operation in `E.22:4.3` within this evaluation.

A complete reusable result must let the reader recover every coordinate, its value or unestablished state, the applicable adjacent-value rationale, and the evidence locus. Choose a form that suits the receiving use and preserves any required serialization. The table shows one sufficient form.

| Coordinate | Value | ShortRationale | EvidenceLocus |
|---|---:|---|---|
| `<E.9.DA coordinate>` | `<0..5; leave unassigned while required evidence is missing or unchecked>` | `<assigned-value basis and the applicable adjacent-value rationale below>` | `<DRR section, row, alternative, source-use row, selected-locus row, accepted-decision row, architecture decision, or missing locus named by value>` |

For values `1..4`, explain why the lower adjacent value would understate the evidence and the higher adjacent value would overstate it. For `0`, explain why `1` would overstate the evidence and what would raise the value or reopen it. For `5`, explain why `4` would understate the evidence and what would lower the value or reopen it.

A reusable coordinate result is incomplete if any required coordinate, its value or unestablished state, the applicable rationale, or its evidence locus is missing. An ordinary bounded review is sufficient when it clearly identifies the checked DRR, the required use and its source, the effective floor, a substantive finding, repaired text or a clean unchanged result, the first action, and the stop or reopen condition.

When required evidence is missing or unchecked, identify the gap. Leave the affected value unestablished until the needed check is complete. Assign a lower value only if checked content establishes the inadequacy in that coordinate's rule. For example, the checked DRR may lack a required decision. If an omitted question changes the answer, reassess each dependent coordinate under its own rule. The question adds no coordinate, and strength on another coordinate cannot compensate.

Common calibration points:

#### E.9.DA:4.5 - Local result status and stop condition

Each status below applies to the DRR under review, required use, effective floor, and qualification window. An ordinary bounded review may state it. Create a C.2.1 aggregate result episteme only when a named later reliance needs that reusable object. A local status neither decides a review nor establishes a gate result, permission, assurance level, or work state.

| Status | Meaning |
|---|---|
| `admissibleForDeclaredAuthoringUse` | Every required coordinate meets its effective floor, no architecture or split blocker remains, and the result states the first drafting action, stop or return, and reopen condition. Any downstream acceptance or authorization uses its own receiving relation. |
| `newFrameRequired` | The DRR appears useful only for a different decision, authoring use, selected-locus set, source-use claim, or qualification window than the required one. This is not an admissible result for the current request; open a new `E.22` frame or repair the DRR. |
| `repairBeforeDrafting` | One or more required coordinates fall below their effective floors for the required authoring use. |
| `splitDecisionRequired` | Several coupled questions need separate decision records or explicit convergence before the current result can be admissible. |
| `holdForArchitectureDecision` | Content object, branch, neighbour boundary, selected locus, structural-view relation, missing-structure return condition, source-use relation, or publication split must be decided before adequacy can close. |

Derive status without compensation across coordinates. An unresolved architecture blocker yields `holdForArchitectureDecision` regardless of the other values. A required split yields `splitDecisionRequired`, and an easier or different use yields `newFrameRequired`. Otherwise, any required coordinate below its effective floor yields `repairBeforeDrafting`. State the required-use source, effective floor, and floor source in either result form so another evaluator can reproduce the conclusion.

When evidence needed for a coordinate is missing or unchecked, that value remains unestablished. Complete the check before drawing a conclusion that depends on that value. An unestablished required value cannot support `admissibleForDeclaredAuthoringUse`. An independently established architecture blocker, required split, or below-floor finding remains usable.

A result carrying `admissibleForDeclaredAuthoringUse` states the first drafting action, stop or return, and reopen condition. A non-ready result states the first repair, split boundary, or architecture question. Add a non-admissible reading only when an independent local ground makes it plausible and action-changing; any later gate or authorization uses a separately defined receiving relation.

#### E.9.DA:4.6 - Compact result form

Keep an ordinary bounded result short. One possible form follows.

```text
E.9.DA bounded review:
  Exact DRR:
  Required authoring use and its source:
  Effective floor and source: <E.9.DA default 3 | predeclared higher floor and exact raising source>
  Actual-host evidence: <required only when a broad authoring rule is selected>
  Substantive result: <findings, including any answer-changing omitted question | repaired text | unchanged checked DRR when clean>
  Status:
  First drafting action or first repair: <include the applicable stop or return condition>
  Most expansive non-admissible overread?: <only when one is locally warranted>
  Reopen if:
```

This form suffices when no named later use needs a reusable coordinate result. A clean focused review may point to the unchanged DRR without a separate clean ledger for the bounded omitted-question search. After an inspect–repair–verify pass, point to the repaired text and its focused verification.

Extend the bounded result when a complete reusable coordinate evaluation is explicitly required or a named later reliance needs exact result identity. Keep the bounded result's content in the extended form.

```text
E.9.DA reliance-bearing result:
  Exact DRR and effective ReferenceScheme:
  Required authoring use, its source, and qualification window:
  Effective coordinate floor map and source:
  CharacteristicSpace and evaluation-spec refs:
  Semantic evaluation Method ref, only when used by the receiving claim:
  A.6.1 assessment application and actual binding refs, only when used:
  A.13 performer-core and A.15.1 Work refs, only when dated U.Work is asserted:
  F.6 attribution refs, only when precise assignment-bound attribution is asserted:
  Evidence basis checked, including the bounded omitted-question search:
  Coordinate results: <each Coordinate, Value or unestablished state, ShortRationale, EvidenceLocus; form as in 4.4a>
  Precision-restoration reading and triggered exact checks:
  Witness and evidence-use refs on which the named use relies:
  Status, first action or repair, bounded overread, and reopen condition: <include stop or return; overread only when independently grounded>
```

Only the reliance-bearing branch requires every coordinate and the exact identities its receiving use needs. Method, application, and Work remain independently conditional. A claim of dated `U.Work` requires the enacted Method, every precise performer's A.13 core, and independent A.15.1 admission. Include an A.6.1 application only if the receiving claim uses that separately established application. Add F.6 only for precise assignment-bound attribution. Downstream status use, assurance, E.19 admission, authority, and drafting permission require their own direct grounds.

#### E.9.DA:4.7 - Structured finding row when reuse needs it

```text
E.9.DA finding:
  DRR version: <DRRVersionRef>
  Declared authoring use: <DRRDeclaredAuthoringUse>
  Coordinate or status affected: <all affected coordinates, statuses, or stop conditions>
  DRR locus: <section, row, alternative, source-use row, accepted-decision row>
  Value or status effect: <value, status, floor, or stop impact>
  Correction direction: <selected answer | selected locus | source-use payload | architecture choice | example | boundary | stop or reopen>

```

Use this row when the finding must be reusable in a structured form. In an ordinary bounded review, you may put the same precise diagnosis and repair direction in the handoff or repaired text. Labels such as `weak DRR`, `needs more evidence`, or `architecture unclear` leave the repair unspecified in either form. Record each independently repairable defect once and identify all affected coordinates or statuses, preserving their distinct values and rationales.

When `E.22`, `E.23`, absorption, or exceptional-improvement framing requests improvement, below-floor claims support finding rows and subsequent repair. Use a proposal row for an above-floor change only when it offers a substantive, non-dominated improvement within the declared authoring use. It might settle the answer more decisively, change the adopted source payload, assign a selected-locus obligation, decide an architecture split or merge, close a rejected alternative, specify a first drafting action or regression case, or remove or relocate apparatus that would otherwise enter the pattern prose.

A value below `5` is not in itself a defect. Stopping at `4` requires loci showing why a further change to decision content is dominated, unavailable, or outside scope.

### E.9.DA:5 - Worked slices

**Ordinary case — an overbroad wording DRR.** `DRR-ROLE-TRIGGER-03@2` selects this answer for an E.10 amendment and its named consumers: “replace every bare *role* with *system role*.” The review request fixes the use as authoring input for that amendment. The E.9.DA default floor is `3`.

Before assigning coordinates, the evaluator checks the wording problem, system-role practice, the strongest meaning-recovery alternative, misuse and recovery cases, and the predecessor text of the affected `A.6.5` consumer. `A.6.5:1` and `A.6.5:4.1` expose the omitted question. Does each occurrence denote a local system-role kind, or does it denote a relation-participant meaning, a declaration-local slot, an assignment, or an ordinary non-terminological use? The answer changes the proposed rule.

Return `repairBeforeDrafting`. The blanket replacement collapses distinct objects and uses into one term. First repair the DRR so it selects recovery of the intended meaning. Write *system role* for the local kind. Where the text denotes an assignment, participant meaning, SlotKind, or ordinary use, name that meaning. Reopen when the revised DRR distinguishes those uses, names the consumers that depend on the change, and the actual-host replay preserves precision and readability. The compact result suffices here.

**Reliance-bearing extension.** Suppose a named later comparison needs one stable result episteme, `E9DA-Result-ROLE-03@1`, but no Method, application, or Work identity. The complete result would still cover every coordinate; the following one-row excerpt shows the level of detail and why this value falls below the floor:

| Coordinate | Value | ShortRationale | EvidenceLocus |
|---|---:|---|---|
| `LexicalAndNamingClosure` | 2 | Value `1` would understate the DRR because it names the target word and selected E.10 amendment. Value `3` would overstate it because the answer still conflates a system-role kind with the assignment, relation-participant meaning, SlotKind, and ordinary word uses exposed by the actual host. | `DRR-ROLE-TRIGGER-03@2`, selected-answer row; `A.6.5:1`; `A.6.5:4.1` |

The effective floor is `3`, so this row contributes to `repairBeforeDrafting`; another high coordinate cannot compensate. The result's bounded search basis names the wording problem, actual host, strongest meaning-recovery alternative, and the omitted question above. This comparison needs no Method, application, or Work reference. Include witness and evidence-use references only if it relies on them.

**Adequate multi-locus DRR.** The DRR selects the precision-restoration move, assigns positive responsibilities to selected loci, states the first drafting action, carries source payload into examples and conformance, and closes only the alternatives needed to explain the answer. The reviewer can judge it from that content and the actual-host replay. A reliance-bearing evaluation may additionally publish coordinate values and an aggregate result, but the ordinary judgement does not wait for that apparatus.

**Architecture-impact DRR.** A checked DRR cites diagrams, graphs, dashboards, or architecture notes. Review the exact DRR against the relevant E.9.DA questions: did it settle the architecture or structure claim, structural-view relation, preserved and lost structure, missing-structure return condition or source-use relation, selected loci, and publication boundary? A description locates material; it is neither the architecture, the decision, nor the assessment result. Open exact Method, application, Work, and result identities only when the reliance uses them; do not open one because another is present.

### E.9.DA:6 - Bias annotation

This pattern favors settling decisions before drafting. A missing decision costs more to repair once several pattern authors depend on it.

A small editorial decision can use `E.9` directly. In an ordinary DRR review, judge the decision, perform the bounded omitted-question search, and identify the first action. This review needs no separate assessment record. When a named later reliance needs an exact reusable result, Method, application, and Work remain independently conditional. If Work is asserted, preserve its evaluator System, enacted Method, and independently established admission basis. An application, attribution, result, evidence use, or receiving status enters through its own claim and grounds. `E.21` covers pattern quality, `E.23` repeated improvement, and `F.19` wording repair, with `E.10` for cues and unresolved meanings.

### E.9.DA:9 - Consequences

| Consequence | Benefit | Cost |
|---|---|---|
| DRR adequacy becomes inspectable before drafting. | Pattern authors get decisions, not source summaries. | Ordinary review touches only the live questions; a complete reusable evaluation covers every coordinate. |
| Architecture selection becomes visible. | By-value but wrong split or merge choices no longer pass as complete distribution. | Some DRRs need architecture repair before drafting. |
| Source mutation is explicit. | SoTA, standards, reviews, audits, and accepted decisions shape decisions rather than decorate them. | Rationale-only sources cannot raise values. |
| The effective floor and required use are reproducible. | Two evaluators can derive the same status without choosing an easier frame after seeing evidence. | The invoking use or E.9.DA default must be named, and every below-floor required coordinate remains noncompensatory. |
| One bounded search tests the DRR's frame before coordinate closure. | The reviewer can identify an omitted question that changes the answer. | To answer that question, the evaluator must inspect the problem, practice, sources, alternative, failure and recovery cases, and the consumers that depend on the decision. Limit the search to what the answer requires. |

### E.9.DA:10 - Rationale

Settle a missing FPF decision in the DRR before distribution so several later authors do not have to make the same choice. For an ordinary review, judge the decision in the DRR using the bounded search for an omitted question and any actual-host replay the decision requires.

A separately requested reusable evaluation or named later reliance can require a complete coordinate result and exact evaluation or result identities. These two review forms let authors keep decision records as concise as the decisions allow and supply the evaluation detail that reliance needs. In either form, adequacy depends on the content of the decision.
